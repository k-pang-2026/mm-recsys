## 문제와 해결

1. 빈 dev Docker 데이터 생성은 임시 폴더와 bind mount가 서로 다른 파일시스템이라 EXDEV로 중단됐다.
   임시 폴더를 데이터 폴더 안에 만들어 atomic rename과 manifest 마지막 게시·기존 파일 보호를 유지했다.
   실제 Docker 빈 mount에서 450상품·120사용자·4,000이벤트 생성, 파일 해시, 동일 데이터 재사용을 확인했다.
2. 재정렬 후보 300개 안에 신상품이 없으면 탐색 슬롯이 있어도 신상품이 나오지 않았다.
   사용 가능한 7일 신상품을 서빙 후보에 확보하고 카테고리 보정 중에도 보호했다.
   후보 300개 상한·등록일·구매 제외를 지키며 전체 카탈로그 ANN Recall@300은 별도로 유지한다.
   full 실제 API 3건 모두 신상품 ≥1개, 탐색 2개, 동일 L3 카테고리 최대 2연속을 확인했다.
3. 최신순이 지원 목록에 없고 기존 레지스트리의 정렬 설정이 재시작·reload 시 재적용됐다.
   `recommend.scoring.strategy`에 `similarity`·`newest`를 추가했다. 최신순은 사용 가능한 카탈로그의 등록일을 기준으로 하며,
   신규 사용자 폴백으로 덮어쓰지 않고 MAB·신상품·다양성 제약을 후속 적용한다.
   모델 무결성과 학습 설정 검증은 유지한 채 추론 정렬 정책만 적용하고, reload 및 CT의 기존/신규 모델 비교에도 같은 정책을 사용한다.
   full 기존 모델에서 최신순 설정으로 서버 재시작·HTTP 3건·실제 reload 후 HTTP 3건을 검증하고 기본 ctr로 복구했다.
4. 앞서 요청한 다크모드 카드 수정도 포함했다. 카드의 고정 밝은 배경을 제거해 Streamlit 테마를 따른다.
   기존 브라우저 다크/라이트 확인과 이번 전체 dashboard 검사 근거를 구분해 유지했다.

등록 7일 판정은 시뮬레이션 기준일 2026-01-01 UTC다. 최신순의 최종 출력도 탐색·다양성 제약으로 단순 날짜 정렬과 다를 수 있다.
새 정렬 목록은 서비스 초기화 때 한 번 만들며 매 요청마다 전체 상품을 정렬하지 않는다.
